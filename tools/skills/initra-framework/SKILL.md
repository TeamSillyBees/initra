# initra-framework

## 执行协议

1. 阅读项目 `AGENTS.md`、`go.mod`、`internal/boot` 和目标模块，确认项目实际使用的 initra 版本与现有代码模式。完成标准：本次改动涉及的入口、依赖装配和测试位置均已定位。
2. 根据需求只读取下表中相关的 reference；涉及业务模块时必须读取 `references/modules.md`。完成标准：每项框架能力都已映射到现有 `pkg/*` API，没有平行实现。
3. 按当前代码实现：boot 负责装配，handler 负责 HTTP 适配，service 负责用例逻辑并按需直接使用 Ent。完成标准：所有新增依赖均由构造函数注入，所有 `/api/` 路由均登记安全元数据。
4. 运行 checker、gofmt、相关测试和 vet。完成标准：修改文件已格式化，检查通过；无法执行的验证及风险已明确说明。

## 跨能力约束

- 业务项目只 import `github.com/teamsillybees/initra/pkg/*`，禁止 import 根仓库 `internal/*`。
- 业务 ID 使用 `idgen.ID`；对外 JSON/OpenAPI 表示为字符串。
- 所有 `/api/` 路由通过 `server.RouteRegistry` 登记 `RouteSecurity`，缺失元数据时保持 fail-closed。
- service 和 handler 不访问 injector；依赖解析集中在 `internal/boot` 和各模块 `providers.go`。
- 密码、token、验证码、session、Authorization、access key 和带密码的 DSN 不进入日志或公开错误。

## 验证

```powershell
go run .agents/skills/initra-framework/scripts/check_initra_usage.go --root .
gofmt -w <modified-go-files>
go test ./... -count=1
go vet ./...
```

修改 initra 框架仓库、模板或 CLI 时，还要按根 `AGENTS.md` 验证根模块和 `examples`，并检查生成项目。
